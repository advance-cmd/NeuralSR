# 数据集：G-Buffer 引导的 2× 超分

这里有两套数据：

- **单帧数据集**（`train/`、`test/`，下面前几节）：成品 LDR 画面（色调映射 + Bloom 之后），随机静止机位。README 表 1 用的是它。
- **多帧数据集**（`seq/`，见最后一节"多帧数据集"）：带抖动的 720p **线性 HDR**（Bloom 之前）+ 运动矢量 + 深度，按连续帧的短序列导出；目标是 2K 下 64 次抖动平均的超采样图。从 s193 起用它。

`train/`、`test/`、`seq/train/`、`seq/test/` 这四个目录很大（约 52 GB），没有放进 git（见 `.gitignore`）。

## 单帧数据集

从自己的 DX12 渲染器（LearnDX12，提交 cfab65a：延迟渲染 + SSAO + Bloom + ACES 色调映射）导出。
同一个机位渲两次：1280×720 一次（输入），2560×1440 一次（目标）。两次的帧序号相同，水面波浪也一样。

### 划分

| | 机位数 | 说明 |
|---|---|---|
| `train/` | 200 | 随机机位 |
| `test/` | 40 | 33 个随机机位 + 7 个 demo 参考机位（id 233–239，`cams.csv` 里名字以 p1–p7 开头） |

测试集的随机机位都在训练没见过的方向：以场景中心 (8, -25) 为圆心，眼睛的方位角在 0°–60° 的归测试集。
机位由 `tools/gen_cams.py` 按固定种子生成，目标点按物体加权抽（铁丝网、木箱、镜子、地砖、测试球、山坡、水面），
视线被山挡住的机位丢掉。

### 每个样本的文件（`{split}/{id:04d}_*`）

| 文件 | 尺寸 | 类型 | 内容 |
|---|---|---|---|
| `lr.png` | 1280×720 | RGB uint8 | **输入**：720p 渲染的成品画面（屏幕上看到的，sRGB 编码） |
| `hr.png` | 2560×1440 | RGB uint8 | **目标**：2K 渲染的成品画面 |
| `albedo.png` | 2560×1440 | RGB uint8 | G-Buffer0 的基础色（已乘贴图，sRGB 编码）；天空 = 0 |
| `normal.png` | 2560×1440 | RGB uint8 | 世界空间法线，存的是 `n * 0.5 + 0.5`；天空 = 0 |
| `mr.png` | 2560×1440 | RGB uint8 | R = 金属度，G = 粗糙度，B = 0；天空 = 0 |
| `depth.npy` | 2560×1440 | float16 | 观察空间深度（世界单位，近平面 1、远平面 1000）；天空 = 0 |

G-Buffer 和深度都是 2K 的：在 2K 下 G-Buffer Pass 只要约 0.25 ms，
贵的是着色（光照、SSAO 等），所以只有着色降到 720p。

像素对齐：720p 的像素 (x, y) 对应 2K 的 (2x, 2y)–(2x+1, 2y+1) 这 2×2 块。
`PixelShuffle(2)` 正好是这个对应关系。

### 训练用的 `.npy`

`tools/pack_npy.py` 把上面的 PNG 另存了一份不压缩的 `.npy`，放在 PNG 旁边（约 9 秒，多占约 10 GB）：

- `lr.npy`、`hr.npy`、`albedo.npy`、`normal.npy`：和 PNG 一样，(H, W, 3) uint8；
- `mr.npy`：只留两个通道，(H, W, 2) uint8，依次是金属度、粗糙度。

测试集另有 `region.npy`（2560×1440 uint8，`tools/make_masks.py` 生成）：0 = 其他（G-Buffer 里有的不透明物体）、
1 = 天空、2 = 水面、3 = 镜子。做法是用深度和机位还原每个像素的世界坐标，看视线先碰到水面、镜子还是不透明物体。
预览见 `regions_preview.jpg`（蓝 = 天空，青 = 水面，橙 = 镜子）。

`np.load(路径, mmap_mode="r")` 打开时不读盘，切片后 `np.array(...)` 只读切出来的那一块。
实测：解一个样本的 5 张 PNG 约 200 ms；从 `.npy` 裁一个 128×128 的 HR 块（6 个文件）约 5 ms。

### 要注意的地方

- **G-Buffer 里只有不透明物体。** 水面、镜子里的倒影、天空都是前向画的，不在 G-Buffer 里。
  水面区域的 G-Buffer 是水底的地形，深度也是到水底的，和成品画面对不上。
  评估时可以按 `depth == 0`（天空）分开统计，水面区域也值得单独看。
- 只有一个场景。测试集换了方向，但物体都是训练里见过的。
- 成品画面已经过色调映射和 Bloom，是 0–255 的 sRGB 值；训练时一般除以 255 变成 0–1。

### 读一个样本

```python
import numpy as np
from PIL import Image

base = "data/train/0000_"
lr = np.asarray(Image.open(base + "lr.png"))        # (720, 1280, 3) uint8
hr = np.asarray(Image.open(base + "hr.png"))        # (1440, 2560, 3) uint8
depth = np.load(base + "depth.npy")                 # (1440, 2560) float16，天空 = 0
```

`preview.jpg` 是几组样本的预览（`python tools/preview.py train:0 test:205` 可以换别的样本）。

### 重新导出

导出用的是 LearnDX12 的临时副本，加了导数据补丁（`tools/export/`）：
每帧按 `cams.txt` 换一个机位，读回后台缓冲、两张 G-Buffer 和深度，写成原始 `.npy`；
然后 `python tools/convert_raw.py <2K 原始目录> <720p 原始目录>` 转成这里的格式。
两轮共 240 × 2 帧，导出约 45 秒，转换约 50 秒；调试层 0 错误 0 警告。

## 多帧数据集（`seq/`，s193）

从 LearnDX12 的工作区（083b92c 之后：最简 TAA 的 Halton 抖动和速度缓冲，加上 s193 补的天空速度、可调相位数）导出，
渲染设置和仓库默认一样（延迟渲染、SSAO、IBL、CSM、测试球显示），只是读回的位置在 Bloom 之前。

### 怎么取帧

- 16 段，每段 32 帧：训练 12 段、测试 4 段（`seq/seqs.csv`）。测试段整段都在方位角 0°–60° 的扇区里（以 (8, -25) 为圆心，和单帧数据集一样），训练段整段都不进这个扇区。
- 路径 5 种（`tools/gen_seq.py`）：`static` 不动 | `pan` 原地转头 0.1–0.5°/帧 | `strafe` 横移 0.03–0.15 单位/帧 | `orbit` 绕目标 0.2–0.8°/帧 | `dolly` 前后推 0.03–0.12 单位/帧。约三分之一的段里测试球在左右动（物体自己的运动）。
  测试集 4 段：12 静止 + 测试球动、13 转头、14 横移、15 绕目标。
- 每段前面多画 2 帧（frame = −2、−1，不导出），让第 0 帧的"上一帧"和速度有意义。
- **720p 和 2K 是两次运行**，时间按"序列帧"走：每个序列帧只推进一步（1/60 秒），2K 那次在同一个序列帧上画 65 次也不推进。所以两次运行同一帧的波浪、测试球完全一样（实测：720p 不抖 vs 2K 不抗锯齿缩小一半，水面 37.9 dB，比其他区域的 30.2 dB 还高）。

### 每帧的文件（`seq/{split}/{段:02d}_{帧:02d}_*.npy`）

| 文件 | 尺寸 | 类型 | 内容 |
|---|---|---|---|
| `color` | 720×1280×3 | float16 | **输入**：带抖动的线性 HDR，③ 透明之后、TAA / Bloom / 色调映射之前（最亮约 240，>1 的像素约 0.3%） |
| `velocity` | 720×1280×2 | float16 | 速度缓冲：这一帧的 uv − 上一帧的 uv（不含抖动；相机 + 物体；天空 = 只跟着相机转） |
| `depth` | 720×1280 | float16 | 观察空间深度（世界单位），天空 = 0 |
| `region` | 720×1280 | uint8 | 0 其他 / 1 天空 / 2 水面 / 3 镜子（`tools/make_masks.py` 的算法，按机位 + 深度反推） |
| `gt` | 1440×2560×3 | float16 | **目标**：2K、时间冻住，64 个 Halton 抖动位置在线性 HDR 里的平均（每个 2K 像素里的盒式滤波）。不是 TAA 的结果 |
| `albedo` / `normal` / `mr` / `hrdepth` | 1440×2560 | uint8 ×3 / ×3 / ×2，float16 | 2K G-Buffer，同一时刻不抖地画的一帧，含义和单帧数据集一样 |
| `hrregion` | 1440×2560 | uint8 | 2K 的区域掩码（只有测试集） |
| `noaa` | 1440×2560×3 | float16 | 同一时刻按 2K 不抖地画的一帧（不抗锯齿），对比用（只有测试集） |

`seq/frames.csv` 每帧一行：`seq, frame, split, jx, jy, ex, ey, ez, tx, ty, tz`。

- `jx, jy`：这一帧的抖动，单位是 720p 像素，x 向右、y 向下。**整幅画面往右下移了 (jx, jy)**：抖过的帧在像素 p 处的值 ≈ 不抖的帧在 p − j 处的值（实测验证过符号）。
  32 个相位（Halton(2, 3) 第 1–32 个点，2× 超分时每个 2K 像素分到约 8 个）按帧号循环。
- 用速度把上一帧拉到这一帧（backward warping）：到上一帧的 `uv − velocity + (上一帧抖动 − 这一帧抖动) / (宽, 高)` 处双线性取。见 `warp.py`、`tools/check_align.py`。

### 要注意的地方

- **水面、镜子的速度是错的**：水面是 CPU 改顶点、前向画的，速度缓冲里是水底地形的速度；镜子里的倒影也一样。训练 / 评估时用 `region` 掩码分开（水面约占三成像素）。
- 轮廓边上的像素：上一帧可能被挡着（遮挡变化），速度再准也取不到 → 多帧网络要有遮挡掩码（s194）。
- HDR 值有大于 1 的（高光），训练时先过 `log(1 + x)`，评估在屏幕空间（× 2^EV → ACES → sRGB，和 Tonemap.hlsl 一样，不加 Bloom）。
- 大小：训练 26 GB（384 帧，每帧约 70 MB），测试 12 GB（128 帧，多了 `noaa`、`hrregion`）。

### 重新导出

1. LearnDX12 工作区复制一份，打上截图钩子（`WIN_POS`、`NO_UI`、`TAA_DT60`……）和 `tools/export/patch_seq.py`，编 Debug。
2. `python tools/gen_seq.py` → `seq/seqs.csv`、`seq/cams_XX.txt`。
3. `powershell -File tools\export\export_seqs.ps1 -Exe <副本>\x64\Debug\LearnDX12.exe`：每段跑 720p、2K 两次（约 40 秒），
   `tools/convert_seq.py` 转格式、算区域掩码、删原始文件。16 段约 10 分钟，调试层 0 错误 0 警告。
